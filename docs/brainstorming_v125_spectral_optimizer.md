# Concept: SWO (Smooth Walsh Optimizer)

## 1. The Core Idea
Standard optimizers like Adam store a full-resolution copy of the moving averages ($m$ and $v$) for every parameter. For a model with $N$ parameters, this costs $8N$ extra bytes (in float32). 

**SWO** proposes to store these states in the **Spectral Domain** using a low-resolution representation (e.g., Walsh coefficients).

### The "Lossy" Advantage
Instead of seeing the loss of precision as a bug, we treat it as a **feature**:
1. **Denoising**: By discarding high-frequency Walsh coefficients, we filter out the "stochastic jitter" of individual gradients, keeping only the structural direction of the optimization.
2. **Memory Compression**: We can store the optimizer state at 1/4, 1/16, or even 1/64 of the original resolution.
3. **Implicit Regularization**: Forces the weights to evolve in a "smooth" or "structured" way, potentially preventing overfitting.

---

## 2. Mathematical Workflow

For each layer with $N$ parameters (viewed as a 2D or 1D signal):

1. **Forward Pass**: Standard.
2. **Backward Pass**: Calculate gradient $g_t$ (Standard).
3. **Spectral Projection**: 
   - Project $g_t$ into Walsh space: $G_t = \text{FWHT}(g_t)$.
   - Keep only $K$ coefficients (where $K \ll N$).
4. **Spectral Update**:
   - $M_t = \beta_1 M_{t-1} + (1 - \beta_1) G_t$
   - $V_t = \beta_2 V_{t-1} + (1 - \beta_2) G_t^2$
   - *Note: $M$ and $V$ are small tensors of size $K$.*
5. **Reconstruction & Step**:
   - Reconstruct full-size $m_{rec} = \text{SmoothWalsh}(M_t)$.
   - Reconstruct full-size $v_{rec} = \text{SmoothWalsh}(V_t)$.
   - Update weights: $W_{t+1} = W_t - \eta \frac{m_{rec}}{\sqrt{v_{rec}} + \epsilon}$.

## 3. Memory Impact Analysis

| Optimizer | State Memory (N params) | Resolution (K) | RAM Savings |
| :--- | :--- | :--- | :--- |
| **Standard Adam** | $8N$ bytes | $1.0N$ | 0% |
| **SWO K=1/4** | $2N$ bytes | $0.25N$ | **75%** |
| **SWO K=1/16** | $0.5N$ bytes | $0.06N$ | **93.7%** |

*Calculations based on storing $m$ and $v$ as float32 coefficients.*

## 4. Open Questions & Risks

*   **Positivity of $v$**: Walsh reconstruction (especially smooth/bilinear) can oscillate. We must ensure the reconstructed second moment $v_{rec}$ is strictly positive to avoid division by zero or imaginary numbers in the square root.
    *   *Strategy*: Perform updates in log-space or clip reconstructed values.
*   **Coordinate Dependency**: Spectral transforms assume the "order" of parameters matters. Does the flat weight matrix of a Dense layer have a "meaningful" spectral structure? 
    *   *Hypothesis*: Yes, especially if the weights are already being generated by spectral neurons (Walsh/DCT).
*   **Compute Overhead**: FWHT is $O(N \log N)$. This adds a cost to every training step. However, for small $K$, we might be able to use a "Partial Walsh Transform" or block-based approach.
